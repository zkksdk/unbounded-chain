# 无界连锁 · Unbounded Chain

7×7 棋盘 · 4 人卡牌对战 · 支持**局域网联机**。

## 运行

浏览器打开 `index.html` 即可，无需构建、无需服务器。

---

## 局域网联机

### 怎么玩

1. **房主**：大厅 → 🌐 局域网联机 → 创建房间 → 得到一个 **5 位房间号**
2. **好友**：打开同一个页面 → 加入房间 → 输入房间号
3. 房主点「开始对局」。空位自动由 AI 补足（最多 4 个真人）

同一 Wi-Fi 下几个人一起打，或者跨网络也行（走 STUN 打洞）。

### 架构

```
房主浏览器  ──WebRTC DataChannel（点对点直连）──  客人浏览器
    │                                              │
    └────────── ntfy.sh（仅用于交换 SDP 握手）──────┘
```

- **房主权威**：房主跑真正的游戏逻辑，每次状态变化广播快照
- **客人只做两件事**：按快照渲染 + 把操作意图发回房主
- **游戏数据不过服务器**：WebRTC 直连，同局域网内点对点直达
- **信令**用公开的 `ntfy.sh` 中转 SDP，只发生在握手阶段
  （用 SSE 长连接订阅，一条连接搞定，避免轮询被限流）

### 相关代码

| 文件 | 作用 |
|---|---|
| `js/08-net.js` | 信令、WebRTC、快照同步、联机面板 UI |
| `js/06-game.js` | 行动函数里的 `NET.mode === 'guest'` 分支：改成发意图而非本地执行 |
| `js/01-config.js` | `let HUMAN` —— 客人连上后会被改成自己的座位号 |
| `js/07-render.js` | `render()` 末尾挂 `netPushSoon()`，房主据此广播快照 |

### 已知限制

- 信令依赖 `ntfy.sh`，被限流时会提示「信令服务限流」，等一会儿再试
- 暂不支持中途加入（开局后再进的人看不到当前局势）
- 断线不自动重连，需要重新加入
- 客人端不显示掷骰动画，直接进入对局

## 界面布局

### 牌桌视图

棋盘居中，四家围坐，本地玩家**永远坐在下方**：

```
              ┌──────────────┐
              │   橙方  ● 12  │   ← 上
   ┌────────┐ ├──────────────┤ ┌────────┐
   │ 紫方 ● │ │              │ │ ● 红方 │   ← 左 / 右
   │   8    │ │   7×7 棋盘    │ │   15   │
   └────────┘ │              │ └────────┘
              ├──────────────┤
              │   你    ● 9   │   ← 下（本地玩家）
              └──────────────┘
```

- 座位按**顺时针**排：下 → 右 → 上 → 左，正好是出牌顺序
- 联机时座位会**自动轮转** —— 无论你坐几号位，自己永远在下方并显示为「你」，其他人按颜色显示
- 当前行动方的座位会亮起金色边框
- 上/下两家是横向胶囊，左/右两家是竖向窄条（手机上只占 32px）

棋盘尺寸用 CSS 变量 `--cell` 控制，窄屏会自动缩小以塞进左右两家之间：

| 断点 | 格子 | 缝隙 |
|---|---|---|
| 桌面 | 58px | 6px |
| ≤1080px | 42px | 5px |
| ≤560px | 38px | 4px |

### 手牌区

底部是手牌 + 操作按钮。手牌**始终按 花色 → 点数 排序**，同花的牌挨在一起，顺子/同花一眼可见。

排序后会按**对象引用**找回选中的那张牌的新下标，所以插入新牌时不会选错。

## 性能设计

### AI：拟人化节奏

AI 不会匀速出牌 —— 它有一个带随机性的「思考时间」模型：

| 动作 | 思考时间 | 说明 |
|---|---|---|
| 抽牌 | 260–520ms | 更果断 |
| 普通出牌 | 380–720ms | 常规思考 |
| 连锁出牌 | 560–1000ms | 要算连锁 |
| 夺取 | 700–1300ms | 要权衡得失 |
| 动作之间 | 130–280ms | 「反应」间隔 |

再加两层随机扰动：

- **12% 概率长考**：额外 +800–1900ms（像在想一步大棋）
- **7% 概率秒出**：时间 ×0.45（明显的棋随手就下）

回合开始时还有 420–1150ms 的「进入状态」延迟。

实测一回合内 7 步的间隔：`2871, 857, 993, 572, 1071, 983, 2816` ms ——
开头一次长考、中间快速连下、结尾又一次停顿，相当接近真人。

配置都在 `js/06-game.js` 顶部的 `AI_PACE` 里，想调快调慢改这一个对象即可。

### 渲染：增量更新，不重建

`renderBoard()` 以前每次 `innerHTML = ''` 把 49 格全删了重建。而格子里的
`.card` 有 `cardDrop` 动画、`.piece` 有 `pieceIn`、`.badge` 有 `badgePop` ——
**每次渲染整盘牌都在重播入场动画**，看起来就是画面一闪一闪。

现在改成增量更新：

- 49 个格子只建一次，之后永不重建
- 每格算一个渲染签名，签名不变就完全跳过
- 卡牌 / 棋子 / 徽章各自比对，**只有内容真的变了才重建 DOM** —— 入场动画只在
  新落的牌上播
- 类名只增删自己管的那些，保留 `burst` / `combo-glow` 这类瞬时特效类
- 手牌同理：牌面没变就只切高亮样式，不重建

实测一次渲染的棋盘 DOM 变更：

| 操作 | 改前 | 改后 |
|---|---|---|
| 选一张手牌 | ~300 次 | **0 次** |
| 落一张牌 | ~300 次 | **22 次** |

### AI：分步执行，不再一口气打完

`aiTurn()` 以前是**同步 while 循环**，一口气把 AP 全花完。AI 有 10 点 AP 就是
10 次全盘重建 + 10 轮粒子/闪屏/震动，全挤在一帧里 → 直接卡住。

现在改成 `aiStep()` 递归分步，**每步间隔 520ms**，视觉效果一件一件播完。

### 特效：AI 回合自动收敛

- **全屏闪光**在 AI 回合直接跳过 —— 这原本是频闪的主因（AI 连锁 9 次就是
  9 次全屏白闪）
- **屏幕震动**在 AI 回合降级到 `shake-s`；玩家自己打到 `shake-xl` 仍保留
- 冲击波层数在 AI 回合限制为 2 层

实测一个 AI 回合：9 次闪光调用 **全部被拦截**，实际频闪 0 次；而玩家自己
连锁时 `screen-flash` 和 `shake-xl` 都正常。

### 粒子：Canvas 化

粒子原本是 DOM 元素，一次连锁要新建约 2000 个节点（686 粒子 + 1372 拖尾）。
现在全部由 `#fxCanvas` 单张画布绘制，一次连锁的 DOM 增量从 **≈2000 降到 +15**。

- 单个 `requestAnimationFrame` 循环，无粒子时自动停止，`document.hidden` 时挂起
- 设备像素比上限 2；同类 DOM 特效有数量上限（`fxCap`）

## 玩法

- **抽牌**：**每回合开始系统自动抽 1 张，不消耗 AP，无需手动操作**
- **手牌**：**始终自动排序**（花色 → 点数），同花的牌挨在一起，顺子/同花一眼可见
- **AP**：每回合 1 基础 + 连锁返还（上限 +10）+ 上回合保留
- **保留机制**：回合结束剩 AP → **保留一半（向上取整），累积上限 5**（确定性，可规划）
- **行动**：出牌 1AP · 移动 1AP · **吃牌 1–2AP** · 过
- **落子规则**：开局第一枚可落任意空格；**之后必须挨着自己的棋子**（区域扩张）

### 吃牌（牌型压制）

贴着目标落子即可吃。判定不看单张点数，而是看**你落子后形成的牌型**：

| 你在目标旁形成的牌型 | 能否吃 | AP |
|---|---|---|
| 单张 | 点数 **>** 对方 | 2 |
| 对子 | 点数 **>** 对方 | 2 |
| **三条 / 四条** | **无视点数** | 2 |
| **同花 ×3+ / 顺子 ×3+** | **无视点数** | 2 |
| **同花顺** | **无视点数** | **1** |

**被吃掉的牌洗回牌堆底** —— 既不退出游戏（保证棋盘能填满），也不进吃方手牌（避免滚雪球）。

设计意图：把「连锁」和「吃」焊在一起。你攒三条不是为了多拿一张牌，而是为了**干掉你单张永远吃不掉的 A、K**，同时拆掉对方的牌型。收益是**位置性**的，不会转化成资源积累。

- **连锁归属**：**只统计自己的牌** —— 贴着敌方的同点数牌不成立
- **连锁**：对子 / 三条 / 四条 / 同花 / 顺子 / 同花顺
- **移动**：棋子**连同底下的牌**一起搬到相邻空格，原格彻底空出（不留残牌）
- **先手补偿**：掷骰先手之外的人，本局第一个回合 +1 AP
- **分数不封顶**：没有「达到 X 分就赢」的设定
- **结束条件**：
  - 棋盘 49 格全部占满
  - 牌堆空 + 全员手牌用尽
  - **连续 8 手无人行动**（防僵局）
- **结算**：即时分 + 场上棋子数 + 每条行/列/对角线（己方 ≥3 枚 +3 分）

### 为什么被吃的牌不能「消失」也不能「进吃方手牌」

| 方案 | 后果 |
|---|---|
| ❌ 消失 | 每吃 1 次永久销毁 1 张牌。**总牌数 52 vs 棋盘 49 格，只有 3 张富余** → 吃第 4 次开始，棋盘**永远填不满**，主结束条件失效 |
| ❌ 进吃方手牌 | 每吃 1 次手牌净 **+1**（普通出牌净 0）→ 手牌多 → 牌型好凑 → 连锁多 → AP 多 → 更能吃，**正反馈滚雪球** |
| ✅ 洗回牌堆底 | 总牌数恒定 52 → 棋盘能满；不进任何人手牌 → 无滚雪球 |

### 牌量节奏

初始每人 5 张，牌堆 32 张。每回合自动抽 1 张，所以整局共 32 次抽牌，
平均每人 8 次 —— 加上初始手牌，每人全程约 13 张牌可打。想加快或放慢节奏，
改 `newGame()` 里的初始发牌数（`for (let i = 0; i < 5; i++)`）即可。

## 规则修正记录

早期版本有一批规则漏洞（含两个会导致对局卡死的崩溃），已全部修复：

| 问题 | 根因 | 修法 |
|---|---|---|
| 💥 移动后 AI 崩溃、对局卡死 | `doMove` 把目的地写成 `{card:null}`、原格留成无主牌；所有夺取判定无条件读 `t.card.v` | 移动改为整格搬走；所有判定加 `t.card` 守卫 |
| 💥 局域网幽灵格 → 选牌渲染崩溃 | 同上，`computeHints` 的夺取扫描踩同一个空指针 | 同上 |
| 连锁不分玩家，能蹭敌方牌刷 AP | `detectCombos` 只比点数花色，从没看 `owner` | 加 `owner` 参数，只统计己方牌 |
| 移动产生「无主卡牌」，永久占格 | `src.owner = null` 但 `card` 留着 | 整格搬走，原格置 `null` |
| 保留 AP 纯随机，不可规划 | `kept = 1 + random(ap)` | `kept = min(ceil(ap/2), 5)`，确定性 |
| 可以无限「过」，对局永远不结束 | `checkEnd` 只看棋盘满/无牌 | 加连续 8 手无人行动的强制结算 |
| 先手无补偿 | 所有人的第一个回合都是 `1 AP` | 非先手首个回合 +1 AP |
| 任意空格可落，没有区域争夺 | `computeHints` 只跳过非空格 | 加 `canPlaceAt()` 邻接限制 |
